## Domains

Dokploy provides two ways to add a domain to your service:

1. **Free Domains** from Traefik.me
2. **Buy a domain** from one of the providers below

<Callout type="warn">
`traefik.me` domains are free, but they are limited to HTTP only. If you want to configure HTTPS for free domains,
you can [Create a certificate](/docs/core/certificates#traefikme-https-setup) and use it in the domain settings.
</Callout>

If you don't have a domain, you can use our integrated free domains from Traefik.me in the Dokploy panel without doing any configuration. However, this is only for HTTP. If you want to have an HTTPS domain you need to buy a domain from one of the providers above.

Domains are supported for:

- **Applications**
- **Docker Compose**

### Requirements (Optional)

We recommend this if you want to have an HTTPS domain — buy a domain from one of the providers below:

- [Cloudflare](https://www.cloudflare.com/)
- [Porkbun](https://porkbun.com/)
- [Namecheap](https://www.namecheap.com/domains/)
- [Name.com](https://www.name.com/)
- [GoDaddy](https://www.godaddy.com/)
- [Domain.com](https://www.domain.com/)

### Add Domain

Associate custom domains with your application to make it accessible over the internet.

- **Host**: Domain name to link (e.g., `api.dokploy.com`).
- **Path**: Specific path where the application should be accessible.
- **Internal Path**: Path your application expects to receive requests.
- **Strip Path**: Removes the **Path** before forwarding.
- **Container Port**: Port on the container the domain should route to.
- **HTTPS**: Toggle to enable HTTPS.
- **Certificate**: Select `letsencrypt` or `None`.

### Understanding Internal Path and Strip Path

<Callout type="warn">
**Warning: Potential Redirect Issues** — ensure your application handles modified paths correctly.
</Callout>

**Internal Path Middleware** — adds a prefix before forwarding to your container.  
**Strip Path Middleware** — removes a prefix before forwarding.  
**Both Together** — strip first, then add internal prefix.

### Container Ports Clarification

The "Container Port" in domain settings is only for routing via Traefik internally and does not expose ports directly.

### Static Build Type

When using the `Static` build type or `Nixpacks` with `Publish Directory`, use port `80` when creating a domain.

### Adding WWW

Use a CNAME record to add `www` and redirect to the root domain via the application’s advanced redirect settings.

## Wildcard Domains

Wildcard domains allow you to route multiple subdomains to the same application without creating individual domain entries.

Examples:
- **Dynamic staging**: `*-dev.dokploy.com`
- **Multi-tenant**: `*.saas.example.com`
- **Feature branches**: `*-feature.app.com`
- **User subdomains**: `*.users.example.com`

### How Wildcard Domains Work

Wildcard patterns are converted to Traefik-compatible regex rules:
- `*-dev.dokploy.com` → `HostRegexp(^[^.]+-dev\.dokploy\.com$)`

<Callout type="warn">
Wildcard domains require proper DNS configuration with a wildcard record pointing to your server.
</Callout>

### Configure Wildcard Domain for Applications

1. **DNS** — Add an A record with `*` (or your pattern) to your DNS provider.
2. **Dokploy** — Create a domain with the wildcard host, set container port, toggle Wildcard Domain, configure HTTPS, then save.

### Configure Wildcard Domain for Docker Compose

Same steps as applications, but select the service in the `Service Name` dropdown.

### SSL Certificates

<Callout type="warn">
Let's Encrypt wildcard certs require DNS-01 validation.  
</Callout>

**Option 1: Individual Certificates (Recommended)** — automatic per-subdomain certs.  
**Option 2: Wildcard Certificate** — covers all subdomains, requires DNS-01 setup.

### Path Prefix Support

You can combine wildcard hosts with paths (e.g., `*-api.example.com` + `/v1`).

### Troubleshooting

- **DNS** — Verify wildcard record with `dig`.
- **Dokploy** — Ensure wildcard toggle is enabled, correct port set.
- **SSL** — Wait for issuance, check Traefik logs.
- **Routing** — Check regex pattern in Traefik dashboard.

### Security Considerations

<Callout type="warn">
Wildcard domains can expose unintended subdomains — validate in-app if needed.
</Callout>

- Validate allowed subdomains in your app
- Rate limit requests
- Monitor unusual subdomain usage
- Restrict wildcard to non-production environments if possible
